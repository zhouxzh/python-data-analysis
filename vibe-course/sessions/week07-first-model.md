# Week 7：第一个预测模型

> 总时长：180 分钟（3 节 × 60 分钟）
> 数据：`report/data/titanic.csv`（主案例）、`data/bank_marketing.zip`（进阶案例）
> 关键概念：特征、标签、训练/测试集、`train_test_split`、逻辑回归、混淆矩阵、准确率与精确率/召回率、目标泄漏、样本不平衡

## 本节结束后学生能做到

- 说清“预测”和“解释”的区别。
- 运行一个最小分类模型，并检查训练集和测试集得分。
- 识别 `duration` 这类“事后才知道”的泄漏字段。
- 不把模型得分直接当成业务价值。

## 课前准备

- 确认 `scikit-learn` 已安装。
- 使用 `report/data/titanic.csv` 时，先让 DSH 读取字段说明。

## 第 1 节：从分析到预测（60 分钟）

### 目标

理解特征、标签、训练集、测试集。

### 教师演示（10 分钟）

让 DSH 先审计：

```text
请读取 report/data/titanic.csv。
输出：
1. shape、dtypes、缺失数；
2. survived 的分布；
3. 哪些列可能适合做特征，哪些列不适合；
4. 是否已经有测试集，还是需要拆分。
不要直接建模。
```

### 学生练习（35 分钟）

1. 运行审计，回答：
   - 为什么不能用 `survived` 同时当特征和标签？
   - 为什么不能用测试集做特征选择？
2. 让 DSH 生成最小代码：
   ```python
   from sklearn.model_selection import train_test_split
   from sklearn.linear_model import LogisticRegression
   from sklearn.metrics import accuracy_score, confusion_matrix
   ```
3. 选择 `pclass`、`sex`、`age`、`fare` 四个特征，训练一个逻辑回归模型。
4. 输出训练集准确率和测试集准确率。

### 复盘（15 分钟）

- 训练集准确率高不代表模型好。
- 数据拆分的随机种子要让结果可复现。

### 本节关键提示词

```text
请基于 report/data/titanic.csv 写一个最小逻辑回归：
特征：pclass、sex、age、fare；标签：survived。
要求：处理缺失值，使用 train_test_split(random_state=42)，
输出训练集/测试集准确率、混淆矩阵和 3 条结果解读。
```

---

## 第 2 节：模型验证与混淆矩阵（60 分钟）

### 目标

不只报告准确率，还要看混淆矩阵和正类比例。

### 教师演示（10 分钟）

让 DSH 输出详细评估：

```text
请评估刚才的 Titanic 模型：
1. 混淆矩阵；
2. accuracy、precision、recall、f1；
3. 解释测试集中真正例、假正例、假负例分别代表什么；
4. 如果我只关心“不漏掉生还者”，应该优先看哪个指标？
```

### 学生练习（35 分钟）

1. 运行评估，检查测试集里正类样本比例。
2. 尝试改变 `random_state` 或删除 `fare`，观察指标变化。
3. 让 DSH 解释：为什么测试集准确率从 0.80 变成 0.78，不一定代表模型变差？
4. 把评估结果保存为 `projects/<姓名>/output/model_metrics.csv`。

### 复盘（15 分钟）

- 准确率在正类很少时可能骗人。
- 每次只改一个变量，才能判断变化来自哪里。

### 本节关键提示词

```text
请基于 Titanic 模型输出完整评估表：
accuracy、precision、recall、f1、混淆矩阵、测试集正类比例。
并用中文解释每个指标在这个业务问题中的含义。
```

## 第 3 节：目标泄漏、不平衡与模型局限（60 分钟）

### 目标

学会主动让 AI 检查“模型有没有作弊”。

### 教师演示（10 分钟）

展示银行营销数据的泄漏问题：

```text
请基于 data/bank_marketing.zip 做分类分析。
先检查哪些字段在“打电话之前”不可能知道。
如果模型用了 duration，请明确警告目标泄漏，
并给出不使用 duration 的版本。
```

### 学生练习（35 分钟）

1. 对比“使用 duration”和“不使用 duration”两个模型的测试得分。
2. 让 DSH 输出“业务上能使用的特征”清单。
3. 在 notebook 中写 3 条局限：
   - 样本不平衡；
   - 字段是事后信息；
   - 相关性不是因果。
4. 让 DSH 扮演反方：找出你的模型最可能失败的 3 种情况。

### 复盘（15 分钟）

- 模型得分高不等于业务可用；先问“预测时我真的能拿到这些数据吗？”
- 最终交付要写“能支持什么决策、不能支持什么决策”。

### 作业

写 100 字：这个模型能支持什么决策、不能支持什么决策。至少提到一个数据风险和一个口径假设。

## 评分要点

| 项目 | 要求 |
|---|---|
| 最小模型 | 代码可运行、拆分可复现 |
| 评估 | 不只报准确率，能解释混淆矩阵 |
| 风险 | 能识别目标泄漏和不平衡 |
| 表达 | 结论区分“统计结果”与“业务建议” |
