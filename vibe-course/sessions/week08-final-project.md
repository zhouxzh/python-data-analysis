# Week 8：结课项目与展示

> 总时长：180 分钟（3 节 × 60 分钟）
> 交付：可复现分析项目 + `report.md` + 3 分钟口头展示
> DSH 能力：plan mode、goal、subagent、workflow、报告审查

## 本节结束后学生能做到

- 把一个模糊选题变成可验收的数据分析项目。
- 用 plan mode 先写方案，再让 DSH 执行。
- 用 goal 管理跨多轮项目，用 subagent 或 workflow 拆独立任务。
- 完成一次“问题 → 口径 → 结果 → 局限”的展示。

## 结课项目要求

1. 选题：可以从下面的清单选，也可以自拟，但必须能被当前数据回答。
2. 数据：优先使用本仓库数据；若自选数据，必须说明来源和许可。
3. 代码：保存到 `scripts/`，能一键运行，不修改原始数据。
4. 输出：至少 1 张核心图、1 张汇总表、1 份 `report.md`。
5. 验证：报告中明确写出“已验证事实 / 待验证推断 / 局限”。
6. 展示：3 分钟，不读代码，按“问题 → 口径 → 发现 → 局限”讲。

## 推荐选题

- 城市空气质量：哪些区域的人均污染强度更高？
- 银行营销：哪类客户更容易订阅定期存款？
- Titanic：哪些特征与生还率相关，模型能否用于“事前”判断？
- 学生成绩：成绩差异来自科目还是学生？
- 自选：使用校园打卡、课程数据、公开开放数据。

## 第 1 节：定义问题与计划（60 分钟）

### 目标

把题目变成“问题、指标、数据、验收标准”。

### 教师演示（10 分钟）

使用 plan mode：

```text
/plan 我要做结课项目：<我的题目>。
请先调查仓库里的可用数据，然后给出：
1. 我到底想回答什么问题；
2. 用什么指标衡量答案；
3. 需要哪些字段和清洗步骤；
4. 核心图和表格是什么；
5. 交付文件和验收标准。
先不要创建代码文件。
```

### 学生练习（35 分钟）

1. 在 DSH 中运行上面的 plan mode。
2. 人工检查方案：
   - 问题是否能在数据范围内回答；
   - 指标定义是否清楚；
   - 是否缺少数据来源和局限。
3. 修改后确认方案，让 DSH 创建项目目录结构。
4. 把最终问题、口径、验收标准写进 `projects/<姓名>/final/README.md`。

### 复盘（15 分钟）

- 一个好项目标准不是“代码多”，而是“别人能复现并理解结论”。
- 计划阶段花时间，执行阶段会快很多。

### 本节关键提示词

```text
请为我的结课项目创建长期目标：
“完成 <题目> 的可复现分析报告”
验收标准：scripts 可运行、output 有图和表、report.md 有 3 个结论和局限。
先从 plan mode 开始，确认方案后再执行。
```

---

## 第 2 节：并行执行与 goal 追踪（60 分钟）

### 目标

用 subagent / workflow 并行推进独立任务，用 goal 持续追踪。

### 教师演示（10 分钟）

对规模合适的项目：

```text
请同时启动两个后台子代理：
A：审计并清洗我的数据，输出 audit.md；
B：检查我已有的 scripts 是否可运行、是否有明显 bug；
两个子代理完成后分别报告，不要相互等待。
```

### 学生练习（35 分钟）

1. 把项目拆成独立任务：
   - 数据加载与清洗；
   - EDA；
   - 可视化；
   - 模型或假设验证；
   - 报告撰写。
2. 使用 goal 让 DSH 按“数据 → 分析 → 图表 → 报告”的顺序推进。
3. 每次 DSH 完成一个阶段，学生必须做一次人工验证：
   - 代码是否真的运行；
   - 结论是否真的来自数据；
   - 原始文件是否未被修改。
4. 让 DSH 写 `report.md` 初稿，然后人工修改。

### 复盘（15 分钟）

- 子代理/工作流适合“边界清楚”的任务，不能替代人的验收。
- 并行任务结果之间出现口径不一致时，必须停下来统一口径，不能硬合。

### 本节关键提示词

```text
请运行 workflow 完成我的结课项目：
阶段：数据审计、EDA 与可视化、报告撰写。
参数：datasetPath=<我的数据路径>、projectDir=<我的项目目录>。
输出：audit.md、eda_summary.md、dashboard.png、report.md。
每个子代理都必须注明依据和局限。
```

---

## 第 3 节：展示与互评（60 分钟）

### 目标

用 3 分钟讲清一个项目，并给出可执行的改进建议。

### 展示模板（每人 3 分钟）

1. 问题：我要回答什么？为什么值得回答？
2. 数据与口径：数据来自哪里？字段怎么定义？
3. 方法与发现：清洗、EDA、模型或验证，核心 1-2 个结果。
4. 局限：什么不能下结论？
5. 下一步：如果再做一次，会改什么？

### 互评表（每组 3 人）

| 维度 | 问题 |
|---|---|
| 清晰 | 3 分钟内是否听懂问题、方法和结论 |
| 逻辑 | 结论是否有数据依据 |
| 可信 | 是否报告样本量、口径、局限 |
| 视觉 | 图表是否信息完整、不误导 |
| 伦理 | 是否避免把相关性说成因果，是否保护数据隐私 |

### 教师总结（10 分钟）

- 8 周后学生带走的不是 API 清单，而是 `问题 → 数据 → 清洗 → 探索 → 表达 → 复盘` 的闭环。
- Vibe Programming 的正确用法：AI 负责第一版和加速，人负责定义、验证、解释和责任。

### 最终作业

提交：

```text
projects/<姓名>/final/
  README.md
  scripts/
  output/
  report.md
```

`report.md` 结构：

1. 题目与摘要；
2. 数据来源与字段说明；
3. 清洗与口径；
4. 关键发现（带依据）；
5. 局限与待验证假设；
6. 数据伦理声明；
7. 附录：DSH 提示词与迭代记录。

## 评分要点

| 项目 | 权重 | 要求 |
|---|---|---|
| 问题与口径 | 20% | 问题清楚，指标可计算 |
| 可复现 | 25% | 脚本可运行，原数据未改 |
| 分析与图 | 25% | 有依据、有样本量、不误导 |
| 结论与局限 | 20% | 区分事实、推断、局限 |
| 展示 | 10% | 3 分钟讲清闭环 |
